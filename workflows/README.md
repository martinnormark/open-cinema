# Workflows

The ComfyUI workflows behind Open Cinema, as API-format JSON. Each file opens in the ComfyUI editor (**Workflow → Open**, or drag it onto the canvas) and can be queued on a ComfyUI server with the same models and node packs, such as Comfy Cloud.

| Folder                                       | What it holds                                                                                                                                                                      |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`cloud/`](#cloud-graphs)                    | Every graph the app runs on Comfy Cloud, **generated** from the code the jobs Worker calls. Do not edit these by hand.                                                             |
| [`background-replace/`](background-replace/) | The Kling 3.0 Omni and SwitchX background graphs with a `comfy-build.yaml`. The app sends the same Kling request through Comfy Router; these are the packaged ComfyUI equivalents. |
| [`character-replace/`](character-replace/)   | The Kling 3.0 Omni recast graph with a `comfy-build.yaml`, the ComfyUI equivalent of the app's Router request.                                                                     |

Image generation (FLUX 3 Image), text-to-video (LTX 2.5 Fast and Pro, FLUX 3 Video) and the hosted edits (Kling 3.0 Omni, Bria's matte) run as single Comfy Router model calls, not graphs; their request builders are in [`packages/comfy/src/workflows`](../packages/comfy/src/workflows).

## Cloud graphs

Built by [`packages/comfy/src/workflows/exports.ts`](../packages/comfy/src/workflows/exports.ts), which calls the same graph builders the jobs Worker submits. [`cloud/manifest.json`](cloud/manifest.json) lists, for each file, the workflow kind that runs it, the loader inputs it reads, the save nodes it writes and every model file it loads.

Every adapter is Lightricks' own; the app uses no LoRA made by anyone else ([third-party-ip.md](../docs/third-party-ip.md)). The base weights (LTX-2 19B, LTX 2.3 22B, LTX 2.5 22B and their Gemma encoders, FLUX.2 Klein 9B, MoGe-2, SAM 3.1) are listed per file in the manifest.

### How the files differ from a live run

- Loader inputs name placeholder files (`source.mp4`, `reference-0.png`, …). In the app the jobs Worker uploads the creator's media and writes the uploaded names into the same loader fields. To run a file yourself, put files with those names in ComfyUI's `input` folder or pick your own in each loader.
- Prompts are fixed examples written by the app's own prompt builders where they exist, and every seed is `20261030`. The app derives prompts from the creator's direction and Elements, and seeds from the job's inputs.
- Variants that depend on the take (frame count, size, pixel aspect) are built for the common case: the media graphs assume square pixels except `square`, and the Re-stage graphs are built for the app's full 97-frame limit (one mesh and render per frame).

### Keeping them in sync

```sh
bun scripts/export-workflows.ts           # regenerate cloud/ after changing a graph builder
bun scripts/export-workflows.ts --check   # exit 1 if any file is stale, missing or extra
bun scripts/validate-workflows.ts         # check every file against Comfy Cloud's node catalogue
```

`apps/jobs/test/workflow-exports.test.ts` compares the committed files with freshly built ones, so `bun run check` fails when a builder changes and the files were not regenerated.

`validate-workflows.ts` reads a server's `/api/object_info` (Comfy Cloud by default, a local ComfyUI URL, or a saved JSON file; nothing is queued and no credits are spent). It checks that every node class exists, every input is one the node declares (dynamic combos and autogrow inputs included), required inputs are set, links connect compatible types, and every model file and other choice is one the server offers.

### Verification, 2026-10-17

- **Node catalogue:** all 25 files pass `validate-workflows.ts` against Comfy Cloud. One note: `ltx-2.5-22b-ic-lora-alpha-gen-0.9.safetensors` is missing from Cloud's `object_info` list, yet the Alpha Gen graph ran on Cloud with that file twice the same day (jobs `f30bd530` and `a32a3cf1`). Re-check before a demo that depends on it.
- **ComfyUI editor:** all 25 files were opened in the ComfyUI frontend 1.55.17, served with Cloud's node catalogue. Every file loaded with all its nodes and no missing node types, and exporting the loaded graph back to API format gave the same nodes, links and values. The only differences were defaults the editor adds for newer optional inputs, and VideoHelperSuite's `start_time`, whose custom widget comes from that pack's frontend extension, which the check did not load.
- **Same graph as live runs:** Comfy Cloud's job history holds the graphs the app and its scripts submitted. Matched node for node, `background/ltx-alpha-gen-image`, `media/lock`, `media/conform`, `performance/pose`, `camera/dolly-in-text` and `experiments/ltx-recast` are identical to graphs that completed on Cloud, apart from uploaded file names, seeds, prompt text and per-job settings (strengths, the recast's target box, the camera run's smaller preview size). The Re-stage, Object Swap and Restyle runs on Cloud used the same node types but were short check runs or earlier revisions of the graph, so they do not match node for node. Cloud's job history has no run of the other variants (the other camera moves and angles, the video plate, pose and depth).
