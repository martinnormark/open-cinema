# Recasting and relocating a moving scene

> Deployment update (2026-10-30): the application now runs entirely in Docker with Bun, SQLite and private file storage. Infrastructure references and earlier verification results below describe the previous implementation. Use [deployment](deployment.md) and [architecture](../ARCHITECTURE.md) for current setup.

Tested on **2026-10-18** on Comfy's 8.4 s street-dance clip (720×1280, 24 fps, 201 frames, high-angle camera following a dancer, with a passer-by crossing in front). The ask: change the character, or move the whole scene somewhere else, while the shot keeps moving. Cal (the character-sheet Character) and the Tide Mill Location were the targets. Clips are in the project files under `moving-scene/`. Graphs and requests are under [`evaluation/moving-scene/`](../evaluation/moving-scene/).

## Verdict

| Ask                      | Best result                                                           | Quality                                                                                                                                                                                                  |
| ------------------------ | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Change the character     | **The app's recast** (Kling 3.0 Omni edit, `video.character-replace`) | 1080p, 24 fps, the real street and the passer-by kept, Cal recognisable (silver hair, charcoal coat, navy sweater). The pre-flight warns `small-face`, and the result held anyway.                       |
| Move the scene elsewhere | **Seedance 2.5 video edit**, now "Move the whole shot" in the app     | The whole shot moves to the estuary: ground, water, mill, reflections. The dancer, the passer-by and the camera move are kept. 720p, 24 fps; one run came back 0.3 s short, the app run was full length. |
| Both                     | Seedance 2.5 relocate, then the app's Kling recast on its output      | Cal dancing at the tide mill at 1080p with the passer-by.                                                                                                                                                |

The app's **background replacement fails on this much camera motion**. Kling draws the tide mill only while the opening frames match the reference; once the camera pans, the original street comes back. The Bria matte lock cannot fix that, because the edit itself reverts.

## Gaps and what would close them

1. **Relocation on moving takes.** Done: background replacement has a third method, `pipeline: "seedance"` ("Move the whole shot" in the composer). It sends the take and up to three Location references to Seedance 2.5 video edit on Router, then the conform media step puts the result on the take's frame grid with its audio. There is no foreground lock, because Seedance rebuilds every pixel. Seedance can retime: the first run dropped the closing tilt and came back 8 frames short, so conform holds the last frame rather than stretching. Kling plus the lock stays the default for small moves. It costs about 190 credits per source second, roughly five times Kling's background edit.
2. **Recast on small faces.** The `small-face` warning is conservative for Kling 3.0 Omni here; the face was about 3% of frame height and still read as Cal at 1080p.
3. **Partner nodes on Comfy Cloud.** Cloud refuses API nodes (`Please login first to use this node`) unless the request carries `extra_data.api_key_comfy_org`; the app keeps calling partner models through Router.
4. **Router video inputs.** Kling and Seedance fetch video by URL. A Cloud input's `/api/view` redirect is a signed six-hour storage link, usable when R2 has no public URL.
